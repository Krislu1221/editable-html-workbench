# v5.12 — 冻结画布的尺子修正 + 混合文字容器不再冻结

> 2026-11-10。两个都是「普通网页（不是幻灯片）」才会踩到的坑，
> 都是把工作台指到真实的业务交付页面（长文档、混排文字）时暴露出来的。
> 改动只在 `assets/editable.js`，没有新接口，没有新文件。

## 1. 「适应」把页面推到屏幕中间，上方一大片空白

**现象**：进入编辑后点顶栏的「适应」，页面整体下沉约 400px，上方留白，
右上角之类的元素被切到视口外。

**根因**：v5.10 的画布锁定把所有块级子元素改成 `position:absolute`，
锚点容器（`.page` / `.slide`）自身的盒子因此塌陷——只剩内边距。
实测一张 1240×1980 的页面塌成 **1240×56**。
`fitCanvas()` 之前直接拿 `s.offsetHeight` 当自然高度，于是：

```
marginTop = (availH - natH * sc) / 2 = (848 - 56 * 0.698) / 2 ≈ 396px
```

垂直居中就用这个错到离谱的高度算出来，页面自然是往下掉。

**修法**：冻结态改用「子元素范围」量真实内容尺寸（`contentExtent()`，页面坐标系、未缩放），
缩放比与居中都用这个值；`marginBottom` / `marginRight` 同理
（原来用塌陷后的 `offsetHeight` 算，放大后也滚不到下半截）。

**判据**：`#f` 里的 `body.getBoundingClientRect().top` 不再出现几百 px 的偏移；
1240×1980 的页面点「适应」后内容仍从顶部开始。

## 2. 混排文字容器里的块级元素被冻结 → 文字被压住

**现象**：形如

```html
<div class="stamp">
  <span class="big">+8.4%</span>
  QoQ 会员活跃<br>样本 324 人 · 6 门店
</div>
```

这类「一个块级 span + 直接挂着的文字节点」的结构，进编辑后大数字叠在「QoQ 会员活跃」上。

**根因**：`display:block` 的 `<span>` 属于「块级盒子」，被冻结成绝对定位后就退出了文档流，
容器里的**文字节点整体上移**，正好被绝对定位的大数字盖住。

**修法**：冻结前先看容器的直接子节点——只要挂着非空白的文字节点，
就跳过整棵子树（不冻结、也不递归）。
这类型容器里的元素本来就不会因为拖动邻居而重排，跳过反而安全。

**判据**：上述 `.big` 的 `position` 在编辑态仍是 `static`，文字与大数字不重叠。
