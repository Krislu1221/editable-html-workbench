# v5.13 — 拖一个东西，它的格式不许变，邻居也不许挪

> 2026-11-10。两个问题都是拿**真实站点**（`oldpal.cn` 主页：带 sticky 顶栏、grid 卡片、
> 手写 `.now li` / `.rules li` 选择器）当靶子测出来的。
> 回归全部落在 `assets/editable.js`，另有两个验收脚本按新语义改写。

## 1. 拖走的元素「格式变成浏览器默认样式」

**现象**：拖一张卡片或一条列表项，位置是动了，但原本的胶囊边框、flex 排版、底色全部消失。

**根因**：拖动时 `toFreeQuiet()` 把元素 **appendChild 到画布级的 `.free-layer`**，
等于把它从原来的 CSS 上下文里连根拔走。手写站点里最常见的写法是
「父类名 + 子标签」：

```css
.now li { display:flex; padding:13px 4px; border-bottom:1px solid ... }
.rules li { background:var(--paper-2); border-radius:12px; padding:12px 16px 12px 52px }
```

元素一旦离开 `.now` / `.rules`，这些选择器全部不匹配 → 浏览器默认样式接管。
同理 `.card h3`、`.col li span` 这类后代选择器在跨层搬动后也会走样。

**修法**：**不再搬。** 画布锁定之后每个块本来就是绝对定位，
换位置只需要改自己的 `left/top`；留在原父节点里，CSS 上下文一个字都不会丢。

配套改动：
- `toFreeQuiet()` 不再创建/搬入 `.free-layer`，只把元素转成绝对定位并记住原始几何；
- 新增 `parentSpaceOrigin(el)`：画布坐标 ↔ 父容器（padding box）坐标的换算，
  拖动 / 缩放 / 方向键 / 面板 X、Y 四处写入统一走它；`boxRect()` 读回时补上原点；
- 撤销恢复不再把元素搬回层里（`restore()`）；
- `backToGrid()` 变成空操作（元素已在原位时不再重排 DOM），只为**兼容旧文件**保留；
- `.free-layer` 机制整体保留但只用于读取历史保存过的文件。

**判据**（`oldpal.cn` 实测）：拖动后 `.roster .card` 仍然 `par=roster`，
`background/radius/padding` 与拖动前一模一样；`.rules li` 仍然 `display:list-item`、
底色与内边距不变；保存后重新打开，位置生效、样式完整、无编辑器残留。

## 2. 拖动时「原位置被其他元素挤占」

**现象**：把一个块拖走，下面的内容立刻往上顶，原来的位置留不住。

**根因**：画布锚点选错了。带 sticky 顶栏的站点里，`body` 的第一个子元素就是那条
62px 的 `.topbar`，它同时满足「宽高 > 40px」，于是被当成整页画布：

```
FREEZE { canvasTag: "DIV.topbar", nodes: 10 }    ← 只冻结了顶栏里那 10 个节点
```

顶栏以外的正文根本没被冻结 → 拖谁都会引起正常文档流重排。

**修法**：
- `slide()` 选画布时**排除 `position:fixed/sticky` 的子元素**（顶栏、浮动按钮不是页面本体）；
- 正文容器只有一个 → 用它；有多个平级块 → 直接用 `body` 当画布，整页一起冻结；
- `freezeInto()` 里 `sticky` 元素不再被冻成绝对定位（冻了就失去吸附效果）。

**判据**：同一页面 `FREEZE` 变成 `canvasTag: "DIV.wrap", nodes: 134`；
拖走第二张卡后，第一、三张卡的页面坐标一个像素都没动。

## 已知代价

画布锁定把几何写成 px 内联样式，保存后文件会变大（`oldpal.cn` 15.8KB → 29.3KB），
并且**响应式会失效**（媒体查询里的网格列宽不再生效）。这是「PPT 式编辑」的固有代价，
需要响应式版式时请勿在同一个文件上反复编辑后直接上线。
